# 评估用例库（Evals）

> 为各领域专家建立**可复现的验收标准**，支撑「评估 → 复盘 → 固化 → 回归」的进化闭环。
> 评估是**人工执行、按 rubric 判定**：把用例的「输入」贴给对应专家（复杂任务交 `orchestrator` 路由），对照「验收要点」逐项打分，把结论写回用例的「评估历史」。

## 目录结构

```
evals/
├── README.md          # 本说明
├── _template.md       # 用例模板（新增用例从此复制）
├── registry.md        # 用例总表（索引，唯一入口）
├── 种植专家/
│   └── PLANT-001-*.md
├── 食品安全专家/
│   └── FOODSAFE-001-*.md
└── ...
```

## 一个用例包含什么

- **元信息**：ID / 专家 / 优先级 / 状态 / 最近评估（供 `registry.md` 汇总）
- **背景意图**：考核什么能力、防止什么失败
- **前置条件**：需要的参考资料、数据、模板
- **输入**：可直接粘贴的自包含任务 prompt
- **期望输出**：结构、必须包含的要素、格式要求
- **验收要点（Rubric）**：可判定清单，逐项 0/1/2 分 + 通过线
- **红线**：不可违反项（臆造标准号、漏标来源/不确定度、越权写文件等）
- **评估历史**：每次运行的日期、版本、得分、结论、执行人
- **失败与固化**：失败症状 → 根因 → 改了哪个文件

## 评分口径

- 每项：`0 = 未达`、`1 = 部分`、`2 = 达成`。
- 总分 = Σ(权重 × 得分) / Σ(权重 × 2)。
- **通过线**：总分 ≥ 90% 且无红线违规；70–89% 为**部分通过**（需复盘）；< 70% 为**失败**。
- 任一红线违规 → 直接判**失败**。

## 状态定义

`未评` / `通过` / `部分` / `失败` / `停用`

## 使用流程

1. 从 `registry.md` 挑用例（优先 P0、状态为未评/失败）。
2. **运行**：把「输入」交给对应专家；跨领域任务交 `orchestrator`。
3. **打分**：对照 rubric 逐项评定，记录红线。
4. **复盘**：到 `retrospectives/` 写复盘，写清根因与固化动作。
5. **固化**：修改 `agent.md` / `SKILL.md` / `references/`，并更新 `EVOLUTION.md`。
6. **回归**：重跑该用例及相关用例，确认不退化。

## 新增用例

```bash
scripts/new-eval.sh 种植专家 soil-fertigation
```

或手动复制 `_template.md` 到 `evals/<专家>/<ID>-<slug>.md`，再到 `registry.md` 登记。

命名建议：`<域代码>-<三位序号>-<slug>.md`，域代码见 `registry.md`。

## 约定

- 每位专家至少 **1 个 P0 用例**，覆盖其核心职责。
- 用例输入必须**自包含**，不依赖口头补充。
- 涉及限量/标准/法规的用例，必须显式检查「是否声明以现行标准为准、是否臆造版本号」。
- 用例是**资产**：失败一个用例，就应该产出一条固化动作。
