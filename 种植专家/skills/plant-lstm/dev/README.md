# dev/ —— 加速改造的验证与基准脚本

本目录是 2026-10 把 `scripts/plant_lstm.py` 从**纯 Python 矩阵运算**改为 **numpy 矩阵运算**时留下的验证工具。
日常使用不需要它们。

## 文件

| 文件 | 用途 |
|---|---|
| `verify_equiv.py` | 等价性验证：新老两版在**同随机种子**下损失/权重/预测必须逐项一致（阈值 1e-9，实测 1e-16 以内） |
| `bench_ab.py` | A/B 性能对比：用 CPU 时间（user+sys）测量，两引擎交替、多轮取最小 |

## 前置数据

两个脚本都需要训练数据 JSON，放在当前工作目录（或用 `PLANT_DEV_DATA` 指定目录）：

```bash
cd dev
python3 ../scripts/plant_lstm.py gen_data --plant 番茄   --weeks 40  --out 番茄_data.json
python3 ../scripts/plant_lstm.py gen_data --plant 金线莲 --weeks 100 --out 金线莲_data.json
```

## 运行

```bash
python3 verify_equiv.py     # 期望：全部通过 ✅
python3 bench_ab.py         # 期望：numpy 版快数倍
```

`verify_equiv.py` 覆盖的用例：

1. 固定结构训练（`adaptive=False`）
2. 结构自适应训练（扩容 + 剪枝）
3. `expand_last` 两层连续扩容 / 三层扩容 / `prune_weak`
4. 多层扩容后继续训练（覆盖"权重列数 > 实际输入宽度"这条与原版一致的路径）
5. 模型 JSON 键一致性、跨版本互读、存-取往返

## 两个写验证脚本时的坑（写别的对比脚本也会踩）

1. **必须先 `random.seed()` 再构建模型**。否则先跑的模型把全局随机流前移，后跑的模型会用到不同随机段，
   表现为"权重差 0.3"这种假差异。曾据此误判为代码 bug。
2. **不要用 `np.clip`/`random.gauss` 的"记录版"包装来对比随机流**——包装是透明的，
   真正的问题是第 1 条；用确定性假 gauss（值由调用序号决定）来验证**摆放是否正确**更直接。

## 结论（2026-10-18，i5-13420H，4 核，机器有 WeChat 等常驻负载）

CPU 时间，两轮交替取最小：

| 场景 | 纯 Python | numpy 版 | 加速比 |
|---|---|---|---|
| ①番茄训练（默认 150 轮） | 4.39 s | 1.15 s | 3.8x |
| ②番茄 2 层 300 轮 window=6 | 51.87 s | 6.66 s | 7.8x |
| ③金线莲训练（100 周） | 8.61 s | 1.95 s | 4.4x |
| ④在线增量学习 | 1.83 s | 0.32 s | 5.7x |
| ⑤预测+绘图 | 0.91 s | 0.90 s | 1.0x |
| **合计** | **67.63 s** | **10.98 s** | **6.2x** |

- ⑤ 无提速是因为它由 `matplotlib` 导入（约 0.7 s）主导，与本次改动无关。
- 小配置的提速被 `import numpy`（约 0.36 s CPU）固定开销摊薄：① 扣掉导入后计算部分约 5.6x。
- 等价性：上述所有用例损失/权重/预测偏差 ≤ 2.2e-16（仅浮点求和顺序差异）。
