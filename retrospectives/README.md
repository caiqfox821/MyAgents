# 复盘库（Retrospectives）

> 每次重要交付或评估失败后，在此写一份复盘：**把实战经验翻译成对 agent/skill/知识库的修改**。
> 复盘的产物不是「总结」，而是**文件变更清单**。

## 目录结构

```
retrospectives/
├── README.md          # 本说明
├── _template.md       # 复盘模板
└── YYYY-MM-DD-<专家>-<主题>.md
```

## 什么时候写

- 评估用例判为「部分 / 失败」时（必写）。
- 交付物被人工大幅返工，或暴露出 agent 知识/流程缺口时。
- 一次跨领域协作跑通后，沉淀可复用的编排模式时。

## 复盘流程

1. 建文件：`scripts/new-retro.sh 种植专家 番茄施肥方案返工`
2. 按模板填写：目标、过程、结果对比、问题清单（现象→根因→影响）。
3. **固化**：每个问题都要落到具体文件（`agent.md` / `SKILL.md` / `references/`）。
4. 更新 `../EVOLUTION.md` 记录本次变更。
5. 补充/修改 `../evals/` 中的对应用例，防止回归。
6. 重跑评估确认。

## 原则

- 只写**可验证**的事实，避免空泛评价。
- 根因要定位到**文件层级**，不要停在「模型不够聪明」。
- 一次复盘至少产出 1 条固化动作；没有动作的复盘视为未完成。
