# 稿件解析与格式转换

> 用途：把用户上传的稿件还原为结构化对象，供合规诊断与定向修订使用。

## 一、支持格式与解析要点

| 格式 | 工具建议 | 抽取内容 | 注意 |
|---|---|---|---|
| `.docx` | python-docx | 标题、段落、表格、脚注、批注、样式 | 保留样式层级以还原章节 |
| `.tex` | LaTeX 解析器 / 正则分节 | section、abstract、\cite、bib | 主文件 + `\input` 合并 |
| `.pdf` | PDF 解析器（兜底） | 文本、版面 | 解析难度高，结果须人工复核 |
| `.bib` | BibTeX 解析器 | 条目类型、字段、DOI | 用于参考文献专用校验 |
| `.ris` | RIS 解析器 | 条目字段 | 同上 |

## 二、内部结构对象

```json
{
  "title": "...",
  "abstract": "...",
  "keywords": ["..."],
  "sections": [
    {"heading": "Introduction", "text": "..."},
    {"heading": "Methods", "text": "..."}
  ],
  "references": [],
  "figures": [],
  "tables": [],
  "statements": {
    "data_availability": null,
    "conflict_of_interest": null,
    "ethics": null,
    "funding": null,
    "author_contributions": null
  }
}
```

## 三、元数据抽取

- **标题/作者/单位**：注意通讯作者标记、脚注。
- **摘要/关键词**：区分结构化摘要各小标题。
- **章节**：Introduction / Materials and Methods / Results / Discussion / Conclusion。
- **图表**：编号、标题（caption）、是否正文内嵌或单独文件。
- **声明**：逐类检测是否存在（`exists` 检查）。
- **参考文献**：解析条目并标注引用样式（编号制 / 作者-年份制）。

## 四、引用格式转换

| 方向 | 要点 |
|---|---|
| 作者-年份 → 编号制 | 正文按首次出现顺序编号，替换为 `[n]`；文末按序号排列 |
| 编号制 → 作者-年份 | 需要作者-年份映射，注意同年多篇加 a/b |
| 样式统一 | 期刊名缩写、卷期页码、DOI、et al. 规则 |

**转换风险**：自动转换仅限低风险格式层面；涉及条目缺失、同名作者、重复条目时标记待确认，不臆造 DOI/页码/卷期。

## 五、盲审版本处理

- 将作者、单位、致谢、基金、伦理审批中可识别信息替换为占位符。
- 自引文献在盲审版中按期刊要求处理（保留/匿名）。
- 保留一份"完整版"用于投稿系统与最终稿。

## 六、解析质量自检

- [ ] 章节未丢失、顺序正确
- [ ] 摘要字数与关键词条数可准确统计
- [ ] 参考文献条目数与正文引用数一致
- [ ] 声明段落是否存在的判定无误
- [ ] PDF 解析结果与原文抽样比对
