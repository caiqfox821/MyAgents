# 编排技能

## 何时使用
跨领域复合任务、需要多方协同、不确定找哪个专家、需要对多份专家产出做汇总校验时。

## 编排流程
1. **目标澄清**：交付物 / 受众 / 期限 / 约束 / 验收标准
2. **拆解**：目标 → 子任务（可独立交付）→ 依赖（前置于谁）→ 负责专家
3. **分派**：并行（无依赖）用 `task` 同时发起；串行（有依赖）按序
4. **交接**：向每个专家传 `目标 + 已知数据 + 约束 + 输出格式`
5. **汇总**：合并为单一交付物
6. **校验**：见质检清单
7. **交付**：执行摘要 + 分工说明 + 来源标注

## 交接协议（传给子专家）
- 任务目标与背景
- 已知输入数据（避免重复提问）
- 约束条件（法规、成本、时间、地区）
- 期望输出格式与详略
- 上游子任务的结论（串行时）

## 依赖编排示例
```
原料问题 ── 种植专家 ─┐
                      ├─→ 食品加工专家 ─┬─→ 食品安全专家 ─┐
                      │                  └─→ 营养专家 ─────┤
                      └─ 发酵专家 ────────┘                │
                                                          ▼
                                                    文档专家
```

## 质检清单
- [ ] 事实一致：数据、单位、标准号（GB/DRIs）无矛盾
- [ ] 领域边界：安全 vs 营养、种植 vs 加工未越界
- [ ] 完整性：所有子任务均有产出与验收
- [ ] 可追溯：结论标注来源专家
- [ ] 合规：引用现行有效标准
- [ ] 格式：符合目标文档规范

## 冲突处理
- 专家结论矛盾 → 补充证据复核；仍不一致 → 提请用户裁决
- 数据缺失 → 明确标注"待核实"，不臆造

